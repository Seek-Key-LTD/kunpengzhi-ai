## 一、辩论产出 MD + 纵向分析

### 1.1 每次辩论输出一个 MD

辩论（模拟法庭/八仙辩论）结束后自动生成 **MD 文件**：

```markdown
# 辩论记录 · {辩题} · {日期/场次}
- 辩题 / 双方立场 / 参与席位
- 完整笔录（各席位发言）
- 结论 / 判词 / 争议焦点
- 关键引用（法条/数据/原文）
- 席位表现摘要
```

存放：仓库 `docs/debates/` 或记忆库（Oracle）——**版本化**（每次辩论一个文件，可追溯）。

### 1.2 纵向分析（跨场次对比）

理论：多次辩论（同辩题 / 系列辩题）应做**纵向分析**：

| 维度 | 分析内容 |
|------|---------|
| **立场演变** | 同一辩题多场次：正反方论点是否深化/漂移（法理引用变化） |
| **法理深化** | 引用条文/数据随时间是否更精确（如《纪律处分条例》88 vs 90 条纠错） |
| **席位表现** | 各 agent（12 内阁/7 花）跨场次的发言质量趋势（辩论技巧/逻辑一致性） |
| **争议焦点漂移** | 焦点是否收敛/发散（辩题推进方向） |
| **产出质量** | 套话率、超字数率、引用准确率的变化曲线 |

**技术路径**：
- 辩论 MD → **结构化提取**（席位/发言/引用/指标）→ 落库（Postgres / Oracle 记忆库）
- **向量化**（原文段落 → embedding，milvus/Oracle vector）→ 语义对比（跨场次论点相似度）
- **时序化**（DolphinDB/Postgres 时间序列）→ 趋势曲线

## 二、代码修改 Delta 可视化（产品经理驾驶舱）

### 2.1 自动运行 + Delta 比对

```
代码修改（commit/push）
  → CICD 自动运行（构建/测试/产出生成）
  → 输出产物（JSON 指标/报告/MD）
  → 与上一次比对 Delta（结构化 diff）
  → 记录：本次新增/变更/删除了哪些能力
```

**Delta 计算**：
- 结构化 diff（JSON 指标对比：函数数、覆盖、产出量、质量分）
- 文本 diff（产出 MD/文档的增删）
- 语义 diff（能力向量：新增了什么能力/方向）

### 2.2 可视化（产品经理视角驾驭方向）

需要仪表盘展示：
- **能力演进曲线**（时间轴：每次提交新增了什么能力）
- **产出趋势**（辩论场次、内容量、质量指标随时间）
- **Delta 摘要**（本次 vs 上次：多了什么/少了什么/方向是否偏移）
- **方向驾驶舱**（产品经理看：内容生产在朝哪个方向走，投入产出比）

### 2.3 技术选型（候选）

| 技术 | 适用 | 现状 |
|------|------|------|
| **Grafana** | 时序指标 + 面板（Delta 曲线/趋势） | ✅ 已有实例（PMM Grafana） |
| **Superset** | SQL BI + 图表（结构化数据分析） | 需部署 |
| **飞书多维表格 + 仪表盘** | 产品经理熟悉、协作友好 | ✅ 已有（N8N 可驱动写入） |
| **Streamlit 驾驶舱** | 自定义 Python 面板（kunpengzhi-ai 内嵌） | ✅ 已有 |
| **Quarto/Evidence** | Markdown 数据报表（静态发布） | 轻量 |

**推荐组合**：
```
数据落库（Postgres/时序）→ Grafana（技术指标趋势）+ 飞书 Base（产品驾驶舱）
辩论 MD → 结构化/向量化 → 纵向分析 → 飞书仪表盘/Streamlit
```

## 三、落地路径（未来）
